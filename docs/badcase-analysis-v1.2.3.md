## 2. 实现边界

- `lib/productMatcher.ts`：最多3个词义候选；具体名称、子类与详情提供证据。销量不能使无关商品进入候选。检索别名不授予商品新功能。
- `lib/marketingOpportunity.ts`：生成阈值仍是60，strong阈值仍是80，路径上限仍是3。新增新闻原文引用与虚构场景约束，拆分中性用途和敏感钩子。
- `lib/prompts.ts`：约束新闻理解、机会、策略和三平台表达；策略不是新增事实来源。
- `lib/contentGrounding.ts`：覆盖本次观察到的量化夸大和几类无依据功效，属于有限规则，不是完整 Claim Checker。未覆盖的事实错误不能据此宣称已消除。
- `lib/llmTransport.ts`：默认最多1次瞬时错误重试，最多3个并发请求。一个模型阶段的总预算默认30秒，包含排队、响应读取、重试与字段校正；401等配置/认证错误不重试。校正最多1次。超过预算仍明确失败。
- `lib/marketingPipeline.ts`：线上 API 与后续评测 Runner 共用同一业务流程，避免修复只存在于其中一侧。首选被拒绝时依次尝试其他候选，最多3个；全部不合适时保留 Reject，服务失败不冒充 Reject。
- 新结果包含执行状态、决策状态、失败阶段与错误码，候选评估保留模型分数、最终分数和规则原因。历史缺失的诊断不补造。

新配置可选：`LLM_MAX_RETRIES=1`、`LLM_MAX_CONCURRENCY=3`；现有 `.env.local` 不改动。

## 3. 验证与验收

`pnpm test:optimization` 包含9项离线回归，全部模型请求由测试响应替代，不访问真实模型或新闻服务。覆盖实际关键词重放、真实历史策略的风险识别、候选回退、敏感规则、瞬时错误恢复、字段校正、失败状态、平台部分失败与限流/超时。

模拟评估器批准食品保鲜袋的测试仅证明候选回退流程，不能证明 EV018 在真实模型上应选该 SKU。测试通过也不能解释为9条真实 Badcase已经全部修复。

验证结果：9/9 优化离线回归通过，5/5 原评测完整性测试通过；lint、TypeScript、生产构建和差异格式检查通过。原始评测文件 SHA-256 检查通过。

真实复测建议先覆盖这9条，再覆盖其余51条，特别包括正常 Reject、天气补水、家庭观赛、敏感健康新闻及禁止商业化新闻，确认没有新增误放行或误拒绝。生成新 Run 记录，保留原始输出和人工结论，人工确认新输出后才能计算修复率。Evaluation v1.1 的最终基线冻结条件仍单独成立；本次不修改其标签或创建最终基线标签。

## 4. 修复优先顺序

1. **Pipeline Reliability**：3条案例；运行失败使整个任务无法完成。先处理重试、限流、校正和诊断。
2. **商品候选检索及回退**：EV022/024为确定性选品错误；EV018的SKU030候选匹配合理，生成决策及标签边界需要进一步确认。
3. **需求与内容证据链**：EV035强行制造消费场景、EV008策略及事实扩写、EV055中性场景误拒。需真实模型和人工联合验收。

以上是工程处理顺序，不自动修改人工 Severity 或最终需求优先级。
